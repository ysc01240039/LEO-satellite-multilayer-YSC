1. CBDP 组件 → 代码映射与可消融性判定
--------------------------------------------------------------------------------
对 algorithm_v2.py / common_utils.py 逐行分析后，论文声称的 4 个消融组件在
Python 路由 benchmark 层面的对应关系如下：

(1) "PDE SNC"（PDE 核检测）
    代码实体：common_utils._detect_cores()
      3D 网格密度场 φ → 高斯平滑（σ = max(0.5, 2·exp(-γ·3.69/5))，γ 仅影响平滑尺度）
      → maximum_filter 找局部极大 → _calibrate_cores 二分搜索阈值，
      目标核数硬编码 n_target=93，接受窗口 [0.4×, 2.5×] = [37, 232]。
    可消融性：【可实现】。用 k-means（相同核数、相同需求加权）替换核检测，
      路由部分（benchmark_cbdp_v3）保持不变。

(2) "SNC Mesh"（核网格层级路由）
    代码实体：benchmark_cbdp_v3() 的核路由部分——每个地面站将 (1-α) 比例流量
      分配到 k_cores 个最近核（核内选最近卫星），α 比例直连最近卫星。
    可消融性：【可实现】。两种实现：
      (a) α=1.0：完全去掉核层级（退化为 Shortest-Path）；
      (b) α=0, k_cores=1：保留层级但去掉多核 mesh 分流（单核路由）。

(3) "Dynamic Reconfig"（动态重配置）
    代码实体：benchmark_cbdp_v3_demand_weighted()（需求加权 φ 场，核随需求调整）
      + algorithm_v2.py Part K 的 24 小时逐时重检测（γ_t = γ·需求比）。
    可消融性：【部分可实现，只能以代理方式】。它是时序特性，静态快照中
      以"需求加权核 vs 均匀权核"作为代理；时序版本用 24h 实验
      （每小时重检测核 vs 核冻结）直接量化。两种都已真实运行。

(4) "Nonlinear Damping κ"（非线性阻尼）
    代码实体：【Python 路由代码中不存在】。κ 只出现在 C++ PDE 时间积分器
      （Project/Project/scan_output/kappa_*.json，γ=2, β=0.6, N=1000, seed=42：
       κ=0.001→290 核、κ=0.1→181 核、κ=1→124 核，单种子且非单调）。
      路由 benchmark 的 _detect_cores 不含任何 κ；γ 也只控制高斯平滑 σ，
      核数被校准窗口钉在 ~93 附近。
    可消融性：【不可实现】。它不是路由组件，在路由 benchmark 层面无对应旋钮；
      其影响只能在 C++ PDE 仿真层面评估，且现有单种子扫描不支持论文声称的效果。

24 小时动态重配置实验（α=0.3, k=3 固定，逐时需求变化，10 种子）：
  配置 A：每小时重检测核 100.72 vs 核冻结 98.56 → 冻结反而好 2.1%
  配置 B：每小时重检测核 108.36 vs 核冻结 103.98 → 冻结反而好 4.0%

真实数据揭示的结论（与论文 fig5 声称的故事相反或不符）：
  1. PDE 核检测相对 k-means 没有任何可测收益：去掉它（k-means 替换）后
     imbalance 反而降低约 10–12%。
  2. 需求自适应核（"动态重配置"的静态代理）同样无收益：均匀权核更好约 7–11%；
     时序 24h 实验中核冻结也略优于逐时重检测（2–4%）。
  3. 唯一有真实大贡献的组件是核层级 mesh 路由：去掉它 imbalance 退化
     +64% ~ +104%。但注意此时退化为 Shortest-Path（76.99/88.05），
     比 Greedy、Nearest-3 都差——即 mesh 层级是 CBDP 不崩盘的关键。
  4. Full CBDP (v3) 在配置 A 下比简单基线 Nearest-3 更差（46.9 vs 40.3），
     配置 B 下略好（46.6 vs 51.7）；CBDP v2 均值更低但种子间方差极大
     （22.9–79.5），结论不稳健。
  5. 核检测本身不稳定：10 个种子的核数在 38–231 间剧烈波动
     （目标 93，校准接受窗口 [37,232]），这是上述方差的主要来源。

4. (c) 无法实现的原声称消融及原因
--------------------------------------------------------------------------------
  -Nonlinear Damping（非线性阻尼 κ）：【无法在路由 benchmark 内实现】。
    κ 是 C++ PDE 时间积分器的参数，Python 路由代码（common_utils.py /
    algorithm_v2.py）中不存在任何 κ。核检测中 γ 只控制高斯平滑尺度，
    核数被校准窗口钉住。κ 对路由指标（imbalance/avg_dist）没有作用通道。
    此外，C++ 侧仅有的 κ 扫描（γ=2, β=0.6, N=1000, 单种子）显示核数
    非单调变化（290/181/124），也不支持"去掉阻尼退化 38.9%"的声称。
  -Dynamic Reconfig：【只能以代理实现】。纯静态 benchmark 中没有"时间"，
    本文第 3 节用需求加权核（静态代理）和 24h 冻结对照（时序代理）两种
    方式尽可能覆盖；两种方式都未观察到重配置的收益。

5. (d) 对 fig5 正确内容的建议
--------------------------------------------------------------------------------
  1. 删除 -Nonlinear Damping 一栏：它在路由层面不存在对应组件，任何数值
     都是臆造。若论文要讨论 κ，应放在 PDE 仿真实验部分并引用 C++ 扫描，
     且需多种子验证。
  2. 若保留消融图，应替换为真实可实现的 3 变体（数据见第 3 节配置 B，
     与论文 benchmark 同一需求配置）：
       Full CBDP        46.62 ± 8.30    1384 ± 311 km     0%
       -PDE SNC         40.96 ± 6.33    1501 ± 148 km   -12.1%
       -SNC Mesh        88.05 ± 25.68    814 ± 14 km    +88.9%
     并诚实标注：去掉 PDE 核检测反而略有改善，说明该组件在当前路由
     benchmark 中未体现价值；真正有贡献的是核层级 mesh 路由。
  3. "Dynamic Reconfig"如要保留，只能以 24h 时序实验呈现（重检测 vs 冻结：
     108.36 vs 103.98，冻结略优 4.0%），结论应是"在当前框架中未观察到
     重配置收益"，而不是声称 +10.8% 退化。
  4. 修正 Full CBDP 数值来源：30.20 抄自 N=500 行；N=1000、γ=1.0 的真实
     值是 46.6–46.9（10 种子均值）。distance 列须整体替换为真实 ~1300–1500 km
     量级，删除 12847 km 等无来源数值。
  5. 更深一层的问题（超出 fig5 但 related）：algorithm_v2_report.json 的
     N=1000 数值已无法由当前代码复现（核数 84 vs 169）。建议重新运行
     algorithm_v2.py 全量 benchmark 并更新报告，且修复 _calibrate_cores
     的宽接受窗口以稳定核数。
